# RAG 全局索引重建契约 v1

## 责任边界

- Java 拥有管理员鉴权、任务状态、重试和审计事实。
- RabbitMQ 只负责安排 Java Worker 执行任务，不保存业务最终状态。
- Python 拥有本地知识索引的构建、校验和安全切换。
- 普通聊天、订单、支付链路不依赖本消息契约。

## Java 到 RabbitMQ

事件必须符合 `schemas/ai-task-requested.schema.json`。v1 事件类型固定为
`ai.task.requested`，任务类型固定为 `RAG_REBUILD`。

```json
{
  "eventId": "f0b147d3-171f-4262-903d-327ae932df3a",
  "eventType": "ai.task.requested",
  "schemaVersion": 1,
  "taskId": "task_01JZXKX9QRDMNBX5B0B0H9QTFJ",
  "taskType": "RAG_REBUILD",
  "occurredAt": "2026-07-15T17:00:00+08:00",
  "correlationId": "request-id",
  "traceparent": "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01"
}
```

## Java Worker 到 Python

Java Worker 使用内部认证调用 `POST /internal/rag/rebuild`。请求和响应分别符合
`rag-rebuild-request.schema.json` 与 `rag-rebuild-response.schema.json`。

`source` v1 固定为 `LOCAL_GLOBAL_KNOWLEDGE`。Python 必须以 `taskId` 幂等：同一任务已经
成功时不得再次构建，需返回原结果并将 `replayed` 设为 `true`。

Python 只有在新索引完整构建并校验成功后才能切换当前索引；失败时旧索引必须继续可用。
